1. §6.3 | Missing branch | The recovery logic for an interrupted `accept` command corrupts the baseline store if step 3 is interrupted between the directory renames and the manifest rename. If `export.old/` and `export/` both exist (step 3b completed but 3c did not), the recovery table assumes step 5 was interrupted and deletes `export.old/`. Because the manifest hasn't been renamed yet, `manifest.json` still holds the old baseline's hashes and build. `status` sees the old `manifest.json` matching the old `verified.json` and reports nothing wrong, leaving a silently corrupted store. | Add a recovery rule for when `manifest.new.json` exists to handle crashes during step 3, for example by rolling back the `export/` and `export.old/` renames.
2. §6.3 | Contradiction | Step 1 of `accept` instructs to "verify every file's hash against the report's digest." This contradicts §6.2, which defines `exportDigest` in `CheckReport` as a single `Sha256` string. A single digest cannot be compared against the hashes of individual files. | Clarify whether `exportDigest` is an aggregate hash of the entire export that is recomputed and compared, or if `CheckReport` should include a list/map of all file hashes.
3. §3.3 | Contradiction | `build_lua_index` states that it extracts definitions such as "an XML frame with a literal name=\"Name\"". However, it also dictates that "Comments and string contents are blanked first." If string contents in XML files are blanked before extraction, `name="Name"` will become `name=""`, making the frame name impossible to extract. | Specify that string blanking only applies to `.lua` files, or that XML frame names are extracted before strings are blanked.

However, every variant of `PatchStatus` (except `BaselineMissing`) strictly requires a `ClientBuildNumber`. If `read_client_build` returns a `BuildUnreadable` error, `status` has no valid `PatchStatus` variant to return. | Add variants to `PatchStatus` that accommodate an unknown client build (e.g., `UpToDateUnknown`, `ExportStaleUnknown`), or make the `clientBuild` fields optional.
